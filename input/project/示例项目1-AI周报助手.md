# 项目：AI 周报助手（个人项目 · 示例）

> 这是一个示例项目描述。换成你自己的项目时，按同样结构写就行：
> 「我做了什么 + 用了什么方法 + 最后结果如何」。写得越具体，判断越准。

## 背景与目标

- 每周要从 20 多个技术公众号和 5 个开源社区采集 AI 资讯，人工整理一次要 3 小时。
- 目标是做一个能自动汇总并生成中文周报的助手，替代人工整理。

## 我做了什么

- 独立完成整个项目：负责数据采集、摘要生成、接口封装与页面联调，代码已开源到 GitHub。
- 用 Python 写了采集脚本，按关键词和发布时间过滤，把原始网页统一成结构化 JSON。
- 接入大模型 API 做分块摘要，再按主题聚类生成周报正文。
- 用 FastAPI 把摘要流程封装成 HTTP 接口，前端页面负责展示和一键导出。
- 写了 Prompt 对照实验：同一批 40 条资讯，比较「一次性摘要」和「先抽取要点再生成」两种写法。
- 调试阶段定位过一个问题：长文超出上下文导致摘要截断，改成滑动窗口分块后修复。

## 技术栈

- Python、FastAPI、Requests、SQLite、Git
- 大模型 API（DeepSeek / 通义千问）、Prompt 模板

## 结果

- 摘要可用率从 62% 提升到 88%（人工抽检 100 条）。
- 整理一份周报的时间从 3 小时降到 20 分钟。
- 在 GitHub 上开源，累计 40+ star。

## 复盘

- 没做过模型微调，摘要能力全部来自 API。
- 没有做用户反馈收集，一键导出之后就没有跟踪使用情况。
