# AI Job Research Agent · 求职尽调助手

投简历之前，先用 10 秒搞清三件事：

1. **这些岗位到底要什么？** —— 多份 JD 交叉比对，找出共同要求并排序
2. **信息从哪来？** —— 每条结论都带来源：文件 + 行号 + 章节 + 原文片段
3. **我差在哪？** —— 对照个人经历，输出「已具备 / 部分具备 / 缺失」三级差距与补齐动作

**默认零依赖、纯离线**（规则 + 能力词典），不需要 API Key 就能跑完整流程；
需要更自然的文字建议时，可以再加 `--llm` 接大模型。

## 快速开始

### 在 PyCharm 里

1. `File > Open` → 选择本项目目录 `D:\codexAbout\projects\AI_Job_Research_Agent`
2. 解释器选任意 Python 3.9+（无需安装任何第三方包）
3. 右键 `main.py` → **Run 'main'**（工作目录默认就是项目根目录，脚本已做兜底）
4. 运行结果在 `output/` 目录：`jd_report.md` / `jd_report.json` / `jd_report.html`

### 命令行

```bash
cd D:\codexAbout\projects\AI_Job_Research_Agent
python main.py                       # 自动读取 input/ 下的 JD 与 input/profile 下的简历
python main.py --min-jobs 3          # 只保留三份 JD 都提到的要求
python main.py --include-single      # 把「只有单个岗位提到」的要求也纳入差距分析
python main.py --formats md,json     # 只产出 Markdown 与 JSON
python main.py --llm                 # 额外让大模型给一段行动建议（需 OPENAI_API_KEY）
```

不想动代码、只想看单份 JD 的分析？把 JD 文件单独放一个目录，用 `--jds` 指过去即可。

## 它到底做了什么

```
JD 文件 ──► 解析：切岗位 / 认章节 / 拆要点
              │
              ▼
         能力标签（词典匹配）──► 跨 JD 统计：覆盖几份、必备还是加分
              │                        │
              │                        └──► 每条要求挂上来源（文件 + 行号 + 原文）
              ▼
简历文件 ──► 经历条目 + 证据强度（有力证据 / 较弱证据）
              │
              ▼
         逐条对照 ──► 已具备 / 部分具备 / 缺失 + 差距说明 + 补齐动作
              │
              ▼
        output/jd_report.md｜json｜html
```

### 三个关键口径

| 指标 | 含义 |
|------|------|
| **覆盖** | 提到该要求的不同 JD 数 ÷ 总 JD 数（`3/3 份 JD`） |
| **重要度** | 按章节加权后除以 JD 数：任职要求 1.0、岗位职责 0.8、加分项 0.5；≥0.8 高、≥0.5 中 |
| **证据强度** | 简历里出现「熟练 / 掌握 / 做过 / 完成 / 上线」等 = 有力证据；只有「了解 / 接触 / 课程」= 较弱证据 |

判定规则（`jd_agent/gap.py`）：

- **已具备**：岗位强调的维度都有有力证据（学历这类硬门槛单独按学位比对）
- **部分具备**：只覆盖了部分维度，或只有「了解 / 课程」级证据
- **缺失**：简历里找不到对应证据（会明确写出还缺哪个维度）

否定表达会被识别：简历写「没做过 Docker 部署」「未接触过向量数据库」，不会被算成已具备。

## 怎么写输入

**JD（`input/*.md`）** —— 支持这些写法，格式越规整结果越好：

```markdown
## 岗位一：AI算法实习生        ← 一个文件里可放多份 JD，靠这个标题切分

**公司**：某某科技             ← 可选，会出现在报告的来源列
**岗位类型**：秋招应届生        ← 可选

**岗位职责**                   ← 识别为「岗位职责」
- 协助完成数据清洗与模型训练

**任职要求**                   ← 识别为「任职要求」
- 熟练掌握 Python

**加分项**                     ← 识别为「加分项」
- 有 Kaggle 竞赛经历
```

章节名也接受 `任职资格`、`岗位要求`、`我们希望你`、`优先条件` 等常见写法；
整份 JD 没有章节标题时，所有要点按「任职要求」处理。

**简历（`input/profile/*.md`）** —— 建议按「教育背景 / 技能清单 / 项目经历 / 实习经历 / 自我评价」分节，
每条写清「做了什么 + 结果如何」。程序会优先读取非「示例」命名的简历文件。

## 输出怎么读

- `output/jd_report.md` —— 人看的完整报告：结论速览 / JD 清单 / 共同要求（含来源清单）/ 差距分析 / 优先补齐清单 / 方法与局限
- `output/jd_report.html` —— 同样内容的网页版，浏览器直接打开，适合边改简历边对照
- `output/jd_report.json` —— 结构化结果，含每条要求的 `source_file`、`line_no`、`quote`，方便二次加工

## 按需要扩展

**加一个新能力项**：在 `jd_agent/lexicon.py` 的 `CAPABILITIES` 里加一条即可，
比如给「多模态」「模型部署」加关键词；`subs` 用来拆维度（如 PyTorch / TensorFlow），`actions` 是该缺口的补齐建议。

**调共同要求门槛**：`--min-jobs 2`（默认）表示至少 2 份 JD 提到才算共同要求；只看 3 份 JD 都要的，用 `--min-jobs 3`。

**接大模型**：

```bash
pip install openai
set OPENAI_API_KEY=sk-xxx
python main.py --llm
```

模型名可用 `--model` 或环境变量 `JD_AGENT_MODEL` 指定，兼容 OpenAI 接口的服务可用 `OPENAI_BASE_URL` 指向自建网关。
调用失败不会影响主流程，只是少一段 AI 点评。

## 局限（请务必知道）

- 词典匹配**不懂语义细节**：JD 里的「无经验也可」「不限专业」这类否定表述可能被误判，建议人工复核。
- 它只能判断「简历里有没有写」，不能判断「实际水平多高」；所以「修改简历表述」和「真的去补能力」要分开看。
- 共同要求来自你喂进去的 JD 样本，样本越大越准。3 份 JD 一般只能看出**这个岗位群的通用底子**，
  角色特有的硬技能（比如大模型岗位的向量库、算法岗位的 PyTorch）往往只出现在 1 份 JD 里 —— 用 `--include-single` 会把它们一并纳入分析。
